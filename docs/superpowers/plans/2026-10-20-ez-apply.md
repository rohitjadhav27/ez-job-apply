# Ez Apply Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A daily pipeline that finds, ranks and emails each person their best new job matches, plus a small web tool to edit application emails and open them pre-filled in Gmail.

**Architecture:** One Python package `ezapply`. The pipeline (`python -m ezapply.pipeline.run`) runs in GitHub Actions, triggered by cron-job.org, and writes to Neon Postgres. A FastAPI app (`ezapply.web.app`) on Vercel reads and edits drafts from the same database. Shared code lives in `ezapply/core`.

**Tech Stack:** Python 3.11, uv, python-jobspy, httpx, apify-client, fastembed, openai (SDK, used against OpenAI-compatible endpoints), psycopg 3 (+pool), Jinja2, FastAPI, itsdangerous, bcrypt, rapidfuzz, PyYAML, pytest, respx.

**Spec:** `docs/superpowers/specs/2026-10-20-ez-apply-design.md`

## Global Constraints

- Python `>=3.11,<3.13` (matches GitHub Actions and the Vercel Python runtime). Dependencies are managed with `uv`; `requirements.txt` is exported for Vercel.
- Zero cost: free tiers only. No Claude/OpenAI paid APIs.
- Resume PDFs (`profiles/*.pdf`) and `.env*` (except `.env.example`) are never committed.
- All times are computed in `Asia/Kolkata`; `run_date` is the IST date.
- `MIN_MATCH_PCT` default `75`; `MAX_AGE_DAYS` `7`; `JUDGE_TOP_N` `30`; `MAX_ITEMS_PER_DIGEST` `25`; `LINK_TTL_HOURS` `72`; `SEND_EMPTY_DIGEST` `true`.
- Final score: `match_pct = round(0.6 × ai_pct + 0.4 × rule_pct)`; unjudged items: `round(rule_pct × 0.85)`; all-LLM-failure: `match_pct = rule_pct`.
- Rule weights: title 30, skills 30, seniority 20, freshness 10, city 5, competition 5.
- Each LLM provider gets 3 attempts (backoff 2 s, 4 s) before the chain moves on; a 429 marks that provider exhausted for the run.
- Digest HTML is table-based with inline CSS only (no `<style>` blocks, no SVG, no scripts), plus a plain-text alternative.
- The live network is never touched in tests. Tests that need Postgres use `TEST_DATABASE_URL` and are skipped when it is unset.

## Review Focus

1. **Job text with odd encodings or huge descriptions** (emoji, `\x00`, 50 KB JDs): must not crash scoring or the DB insert. Truncate the description to 8,000 characters and strip NUL bytes in `normalize_item` (Task 4 test `test_normalize_strips_nul_and_truncates`).
2. **Same job from two sources on the same day** (LinkedIn + Naukri): must appear once. Covered by `item_key` (Task 4 test `test_same_job_two_sources_one_key`).
3. **The workflow triggered twice on one day** (cron-job.org + the backup schedule): no second email. Task 10 test `test_second_run_same_day_sends_nothing`.
4. **A logged-in person opening the other person's draft URL**: must 404, not show the draft. Task 11 test `test_cannot_open_other_persons_draft`.
5. **An LLM returning JSON wrapped in prose or code fences, or with a missing key**: parsed or repaired, never a crash. Task 5 test `test_extracts_json_from_fenced_reply` and `test_missing_key_triggers_next_provider`.
